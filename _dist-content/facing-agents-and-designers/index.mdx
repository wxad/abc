在 [小 p: 一次关于 AI 的交互实验](https://wxad.design/abc/small-p) 中，我探索了**和** AI 做些事情，赋予了 AI 鼠标指针（当时 OpenAI 的 Computer Use 还没有发布）：

> 对我来说什么是有趣呢？与 AI 的联系和交互方式。大部分人在用 AI 去做东西，用 AI 去完成其他事，却很少探索和 AI 做什么 —— 真是“无聊”（不负面的中性词）。

回到真实的工作流程后，我发现我们每个人都在做许多事，但好像它们只面向 Agent。我们把个人知识库、Skill、代码 Snippets 都灌给 Agent，期待它回复我们一份惊喜，尽管往往会感到失望。

通过接下来的三个项目，我尝试面向 Agent，也面向设计师，希望能给你一些启发。


## 动画词汇表

关于如何更好地制作交互动画，我在寻找一些和 Agent 更高效沟通的方式。我是想蒸馏一些东西出来的，但是一直找不到方法。我遇到了以下两个问题：

1. 拿来就用的效果库有很多：[fancycomponents](https://fancycomponents.dev)、[magicui](https://magicui.design)、[aceternity](https://ui.aceternity.com)、[cult-ui](https://cult-ui.com)，但：  
   它们更多面向 SaaS 产品、看似丰富，有多少是实用的？以及，实际业务的动画每次都不同，一键复制的意义大吗？  
   我自己也很少需要过去做过的案例。大家的项目都不同，期望它们通用是一件不太现实的事情。  
   我们往往能做到反过来剖析一个动画的感觉或品味，但是面对每次不同的需求，这种反向的经验和“成品”很少有用。  
      
   —— **有什么比一键复制“成品”更可能有用？**
   <br />

2. 我们和 Agent 的对话过程，经常伴随没有信息量的输入输出：“参考一下这个视频”、“我要流畅一点”、“做个轮播”、“看一下这个网站的效果”。  
   我在 [这篇文章](https://wxad.design/abc/interactive-design-in-ai#%E5%88%B6%E4%BD%9C%E5%89%8D) 提到过自己是怎么提供信息量的。长篇大论、生怕漏考虑了什么，几乎把实现逻辑说完，就差动手做了。  

   —— **不能长篇大论，但是如何提高沟通的信息量？**

---

我看到了 Emil 的 [Animation Vocabulary](https://github.com/emilkowalski/skills/blob/main/skills/animation-vocabulary/SKILL.md)，一下就觉得特别有意思 —— 他在解释词汇，这很少有人在干。词汇就是沟通的媒介。但我在想如何更有用？面向设计师，也面向 Agent。

受其启发，我做了一本更加面向设计师、更丰富的 [动画词汇表](https://wxad-design.woa.com/animation-vocabulary)，涵盖 80+ 动画词汇，在解释的基础上加上了使用场景、技巧、小心、提示词，以及案例 —— 业务中实际完成过的案例，而不是 demo：

<ReviewDemo src={facingAgentsVideoSrc.reviewDemo10} note="动画词汇表" clipInset="3px 0 0 0" />

这一份内容，在面向 Agent 时则是一份 Skill，包含了沟通、实现和检测。其中沟通最重要：

1. 建议做什么？
2. 具体用什么方法做？
3. 不建议怎么做？为什么？

在上面的输出中，有一个我认为很有用的点，就是会列举具体的方法。如果你不确定它的意思，你可以点击跳转到具体的页面，查看刚才说到的解释与案例。

1. 对于放大的过程，Agent 提到的词有：[共享元素过渡](https://wxad-design.woa.com/animation-vocabulary#term-3-3)、[形状变化](https://wxad-design.woa.com/animation-vocabulary#term-3-2)、[感知源动画](https://wxad-design.woa.com/animation-vocabulary#term-2-7)、[连续性过渡](https://wxad-design.woa.com/animation-vocabulary#term-3-1)；
2. 对于其他的元素，Agent 提到的词有：[平移](https://wxad-design.woa.com/animation-vocabulary#term-2-0)、[淡入/淡出](https://wxad-design.woa.com/animation-vocabulary#term-0-0)、[隐喻](https://wxad-design.woa.com/animation-vocabulary#term-11-10)、[阻尼](https://wxad-design.woa.com/animation-vocabulary#term-7-2)；
3. 对于关闭的动画，Agent 提到的词有：[可中断动画](https://wxad-design.woa.com/animation-vocabulary#term-7-8)。

## 讨论与走查

## 设计语言的维护

在以往的桌面端项目中，我们都是先维护一个稳定的设计语言，再去搭页面。但如果这件事反过来 —— 当我们“先开发再设计” —— 如何进行组件治理呢？这并不是一个假设，而是一个现实问题，一个如果你不断堆砌功能后会面临的问题。

我们做了一个 **比较和校准设计语言的 Playground**。

AI 让“增加变体”变得容易，UI 为什么不可以像生图一样“抽卡”？不仅仅是字体、圆角这些 CSS Variables，如今完全还可以是 Icon 库、组件变体、间距、版式等等。我们本来就是野蛮生长起来的。那就让 AI 帮我们看看 UI 可以长成什么样：

## 最后

昨天，Ryo 在 AI Engineer 上分享 [《当我们什么都能做，还知道自己想做什么吗？》](https://x.com/ZinkLu2/status/2118357855782965560)，说了许多让我共鸣的话：

> 我不是先想成为设计师，才做这些事。我只是喜欢、好奇、想靠近一点，想看看自己能不能也做出那种感觉。  
> 后来，喜欢真的变成了工作。这很幸运。  
> 可以靠自己在意的事情工作、生活，也可以遇到一群同样在意的人。  
> 但慢慢地，好奇变成规划，游戏变成产出，品味变成了你必须替别人负责而做出的决定。  
> 你越来越能回答：这有没有价值？什么时候能上线？  
> 却不一定还记得，当没有人需要你做这些事的时候，你为什么已经想做了。  
> 我不想用“机器永远不会有某种能力”来安慰自己，因为这个界限一直在变。  
> 我比较想保留的是，我跟“做东西”这件事情的关系。

我想到为什么自己每次尝试用 Cursor 的 Agent 模式都不顺手，而切回 IDE。因为我总觉得它只给我接受与拒绝的选项。我甚至无法通过 `CMD + N` 创建一个新文件，取而代之的是创建一个新对话。我也不需要多个 Parallel Tasks。

它好像没有让我更加参与，而是在证明我越来越不需要参与。重要的是：我想理解的时候，有路可以进去。我想改的时候，有地方可以接手。

我们做了许多只面向 Agent 的事，我们把个人知识库、Skill、代码 Snippets 都灌给 Agent。我们恨不得一次对话就给出一个完美的结果，因为和 Agent 沟通的过程实在太痛苦了。

但是现在 AI 做交互就是很差劲。你想要靠描述、一个截图、一个视频，还原都还原不好。比起这样不合适的期望，我更希望做一些面向 Agent、也面向设计师的事。这样的事也会更加有趣，就像走查的小工具、组件的探索方式。

过去，我面向工程，也面向设计；现在，我面向 Agent，也面向设计师。
